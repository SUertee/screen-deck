# ScreenDeck

以主工作台和 Mac 屏幕顶部小浮窗协作的任务管理工具。管理本地任务、子任务与工作线索，并在中断后找回下一步；真实 Agent 执行仍待接入。

原生 SwiftUI + AppKit 开发原型，macOS 14+。本地任务无需 Obsidian、云账号或 AI。屏幕记录与本机 AI 都是可选功能，必须由用户主动开启。

## 目前能做什么

- 悬停顶部入口展开，点击外部收起；固定或编辑时保持展开，支持“减少动态效果”。
- 默认吸附带刘海的内置屏；无刘海时优先内置屏，仅外接屏可用时回退到系统主屏。显示器配置变化会重新定位，浮窗位置与录屏范围相互独立。
- 本地任务新建、改名、完成、重新打开，以及子任务添加和勾选。
- 同一 Deck 内查看“接续 / 子任务 / 记录”，没有独立编辑窗口。
- 黑白三栏主工作台：左侧四入口、中间本地对话草稿、右侧任务详情；原生窗口按钮与内容顶栏一体化。
- 右侧展示真实手动子任务进度、分工草稿、接续时间线与材料；AI 未连接和交付物空状态明确标注。
- 主工作台浅色黑白、Deck 深色黑白；设置附着在主窗口上，主窗与小浮窗按同一任务 ID 联动。
- 手动保存进度、下一步和网页材料，退出重启后读取最后保存内容。
- 显式选择一块或多块屏幕，默认每 60 秒截图并使用本地 Vision OCR 识别文字。
- 工作记录保留时间、显示器、采样时前台应用、截图和识别文字；可按会话、屏幕、关键词查找。
- 暂停后生成可编辑的本地线索草稿；这不是 AI 完成判定。
- 可选调用本机 Ollama 整理接续草稿：先预览文本，再明确确认；校验来源，保存仍由用户决定。
- 从草稿排除无关记录，或将一次已停止会话的原始记录移到废纸篓。
- 读取错误不冒充空列表，保存失败不伪报成功；中断会话重启后保持停止。
- 显式关联项目并只读查看任务与执行记录；五字段 v2 身份留在项目，私人历史按 project_id 存于用户数据区，旧项目需明确迁移。
- 用户偏好使用 TOML；设置中可查看项目配置声明，并确认将旧本机数据复制到 `~/.screendeck`，保留旧目录。

这不是 Screenpipe 的完整替代品：没有连续视频回放、音频转写、跨设备同步、通用桌面自动化或自动任务完成判定。

## 运行

需要 Swift 6 工具链与 macOS SDK。

```bash
git clone https://github.com/SUertee/screen-deck.git
cd screen-deck
swift run ScreenDeck
```

也可用 Xcode 打开 `Package.swift`。应用常驻菜单栏，不显示 Dock 图标。

为了让 macOS 权限明确关联到应用，可构建本地预览包：

```bash
zsh scripts/package-local.sh
```

脚本在全新的临时目录构建 Release 并输出 `ScreenDeck.app` 路径，使用临时签名，不安装、不覆盖现有应用、不自动启动。它不是经过 Developer ID 签名和公证的公开发行包。移动路径或重新签名后，系统可能要求重新授权。

**先退出旧实例再打开新版本。** 不要同时运行多个实例；旧版本不理解新增记录字段，不应与本版本交替修改同一数据文件。

## 使用

1. 悬停刘海，或从菜单栏展开 Deck。
2. 点击工作台右上角加号，在列表内输入任务名称，Return 保存。
3. 点击名称进入详情；铅笔修改名称，“子任务”页添加和勾选步骤。
4. “接续”页可以直接写一句进度，保存下一步和材料，不需要录屏。
5. 如需采集：齿轮 → 屏幕记录 → 授权并刷新屏幕 → 选择范围和间隔 → 保存设置。回到任务详情点击“记录屏幕”，核对本次范围并同意后开始。
6. 在任务详情暂停后核对线索草稿，再保存接续卡。“继续任务”只打开接续内容，不自动录屏。
7. “记录”页查看原图与文字，过滤屏幕/会话，查找关键词。

任务和子任务的完成由用户勾选。窗口切换、阅读时间、截图变化都不直接等于完成或分心。

材料仅接受完整 HTTP/HTTPS 链接，点击后才打开；不会自动恢复整个桌面。主工作台的对话草稿自动保存到本机，写入失败会保留内存输入并提供重试；Deck 接续编辑、尚未提交的改名和子任务输入仍需手动保存，强制退出可能丢失未保存文字。

## 可选本机 AI

先在“设置 → AI”填写已安装的 Ollama 本地模型名称并保存，再在接续页选择“本机 AI 整理”，预览将发送的文本，确认后生成。保存模型配置不会调用模型。

- 固定请求 `127.0.0.1:11434/api/chat`，禁用 HTTP 重定向，不配置云端密钥。
- 最多使用最近 6 条未排除记录，每条最多 2,000 字符；不发送截图。
- ScreenDeck 不下载模型、不启动模型服务，也不会在后台自动调用。
- 请使用本地模型，不使用云模型；本机服务是否另行转发取决于其自身配置。含 cloud 的模型名称被拒绝，但这不能替代对服务配置的检查。
- 模型超时、格式或来源无效时不保存结果，仍可使用本地线索草稿。
- 来源校验只证明引用 ID 存在，不能证明 AI 的解释正确。模型输出只是待用户确认的建议，不会执行指令或自动勾选。

## 数据与隐私

设置页可查看数据目录：

| 内容 | 新安装 / 确认迁移后的 `~/.screendeck` 位置 |
| --- | --- |
| 用户偏好 | config.toml：默认固定展开、屏幕选择、采样间隔、本地摘要模型 |
| 本机任务、子任务、当前选择、接续卡、独立草稿 | tasks/local-workspace.json，保留兼容聚合格式 |
| 项目位置 / 浏览选择、项目内未发送草稿 | projects.json、conversations/project-drafts.json |
| 会话、OCR、截图 | artifacts/WorkSessions/会话 UUID/ |

已有旧数据时仍使用 `~/Library/Application Support/ScreenDeck`。在「设置 → 数据与隐私」确认迁移后，应用校验并复制旧记录、将偏好转换为 TOML，最后发布切换凭据；冲突或失败不覆盖旧数据，旧目录原件保留。迁移后不要运行旧版本继续写旧目录，否则两边可能分叉。

项目目录中的 `.screendeck/project.json` 与可选 config.toml 保存共享身份和约定，不保存账户、密钥或私人聊天。私人项目历史在 `~/.screendeck/projects/<project_id>/` 的 tasks/runs/artifacts，history.json 绑定实际项目位置；旧 v1 项目在显式迁移前仍按原位置读取。迁移保留原件备份，正式 docs 不搬走。配置声明不执行命令，也不表示已经连接 coding Agent。

项目历史迁移与上面的 Application Support 本机数据迁移相互独立；不会迁移账号、改变旧本机任务来源或自动启动采集。显式维护入口：

```sh
swift run ScreenDeck --migrate-project-history /绝对项目路径
swift run ScreenDeck --inspect-project-history /绝对项目路径
node scripts/validate-project-workspace.mjs --root /绝对项目路径
```

不在两个版本之间交替维护同一项目。私人附件引用采用 `screendeck://<project_id>/artifacts/...`，由工作台解析；普通 Markdown 阅读器或他人电脑不保证能打开，分享附件需另行导出。

- 只有主动开始的会话才采集；打开应用或详情不会开始录屏。
- 保存设置不会开始记录；配置跨重启保留，但每次开始仍需确认。记录期间先停止才能修改配置，屏幕不可用时需重新核对。
- 选定屏幕上的其他应用及敏感内容也可能被记录，不保证只包含当前任务。
- 本轮不读取辅助功能树、不采集摄像头、麦克风、按键或剪贴板，不读取第三方私有数据库。
- 本地文件**未加密**；截图不是脱敏版本，请谨慎选择屏幕。
- 收起时有记录点；Deck、设置、菜单栏均可停止。退出、休眠或用户会话离开时停止，不自动恢复。
- 权限撤销、显示器移除、存储失败停止采集，不静默改用另一块屏幕。
- 一次会话最多 240 条画面记录；无自动过期删除，请自行清理。排除摘要不等于删除。
- 会话移到废纸篓后可以从废纸篓恢复；已保存接续卡仍含原摘要，需另行修正。恢复目录后需重启应用重新读取。
- 原子写入不等于备份、加密或绝对断电安全。旧数据可读取，损坏数据不会被静默重置。

默认无网络请求。仅用户确认本机 AI 操作时调用回环服务；打开材料链接是用户发起的浏览器行为。

## 验证与代码结构

开发约定见 [AGENTS.md](AGENTS.md)。本地 `AGENTLOG.md`（如有）保存任务摘要、执行记录、验证与下一步，已被 Git 忽略，不随仓库克隆或推送；它不是版本发布日志，也不代表应用已经支持自动记录开发过程。

```bash
swift test
swift build -c release
```

迁移路径后可用独立构建目录：

```bash
swift test --scratch-path /tmp/screendeck-local-build
```

测试包括本地存储、旧格式、接续来源、会话恢复、双屏模拟采集、暂停竞态、权限撤销、失败保护，以及隔离样例的原生视图渲染。模拟测试不能代替实际录屏授权、显示器拔插、中文输入法、长时间性能和真实模型效果验收。

```text
Sources/ScreenDeck/
├── App/                  生命周期、设置、任务状态
├── Features/Deck/        面板、热区、动效
├── Features/Theme/       共享语义配色与主要按钮
├── Features/Settings/    设置页、配置草稿与持久化
├── Features/Resume/      接续记录与历史编辑组件
├── Features/WorkMemory/  会话、同窗工作台、线索整理、本机 AI
└── Services/
    ├── Capture/          ScreenCaptureKit 与 Vision
    ├── Configuration/    TOML 白名单、来源校验与保存
    ├── Storage/          私人位置解析、安全持久化与显式迁移
    └── Obsidian/         历史适配代码，当前未接入
```

界面与采集使用 Apple 框架，TOML 解析依赖 TOMLKit 0.6.0 / toml++；未引入或复制 Screenpipe 代码与资产。不能仅凭这一点保证任何比赛的原创资格；参赛时应如实披露既有项目基础、开源依赖及 AI 辅助开发。
