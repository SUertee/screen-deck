# ScreenDeck

一个吸附在 Mac 屏幕顶部的轻量任务面板。悬停刘海查看任务，编辑或勾选后直接写回 Obsidian 日记，完成查看后点击面板外收起。

当前为 **macOS 原生开发原型**，使用 SwiftUI + AppKit。已实现本地 Obsidian 任务读写和顶部 Deck 交互；任务接续、AI 和硬件配件仍在规划中。

## 当前能力

- **悬停展开**：在顶部入口停留约 160ms 展开，无需点击；刘海宽度根据系统屏幕信息计算，无刘海屏幕使用顶部中央入口。
- **按需收起**：展开后移出鼠标不会自动关闭，点击外部收起；支持固定展开，编辑时阻止外部点击收起。
- **全黑 Deck**：空状态为 360 × 200pt，有任务时为 540 × 300pt；内容可滚动，任务标题支持多行显示。
- **直接读写日记**：从 Obsidian 的 Daily Notes 配置定位今日日记，每 2 秒刷新任务；编辑期间暂停轮询。
- **任务操作**：勾选完成、取消完成、编辑文字；修改写回原 Markdown 文件。
- **编辑反馈**：Return 保存、Escape 取消；编辑期间点击收起会确认是否放弃修改，保存失败显示提示。
- **低干扰入口**：菜单栏常驻，不显示 Dock 图标；支持系统“减少动态效果”。

不需要独立 HTTP 桥服务或云端账号。应用本身是一个常驻进程，需要文件读取和写入权限。

## 环境要求

- macOS 14 或更高版本。
- Swift 6 工具链，以及可用的 macOS SDK（例如安装 Xcode）。
- 一个包含 Daily Notes 配置的本地 Obsidian vault。
- 当前以源码运行方式使用；此仓库没有提供经过本说明验证的签名、公证 DMG 安装流程。

## 从源码运行

```bash
git clone https://github.com/SUertee/screen-deck.git
cd screen-deck

SCREENDECK_VAULT="/absolute/path/to/your-vault" \
SCREENDECK_TASK_SECTION="今日主要任务" \
swift run ScreenDeck
```

也可以用 Xcode 打开 `Package.swift`，在运行配置中设置相同的环境变量。

建议先用测试 vault 体验，因为勾选和编辑会直接修改 Markdown 文件。应用启动后，将鼠标移到刘海处；也可以点击菜单栏清单图标，选择“展开 / 收起 Deck”。

### Vault 配置示例

ScreenDeck 读取 vault 下的 `.obsidian/daily-notes.json`，例如：

```json
{
  "folder": "Daily",
  "format": "YYYY-MM-DD"
}
```

在 `Daily/` 中创建当天日期对应的 Markdown 文件，内容例如：

```markdown
## 今日主要任务
- [ ] 整理竞品资料
- [ ] 编写项目总结
- [x] 确认演示场景
```

这里的文件名必须与当天日期和配置格式一致。ScreenDeck 不会自动创建缺失的日记或配置文件。建议先使用上述简单日期格式；自定义日期格式并非全部支持。

### 环境变量

| 变量 | 用途 |
| --- | --- |
| `SCREENDECK_VAULT` | vault 的绝对路径。建议明确设置，避免使用代码内的开发者默认路径。 |
| `SCREENDECK_TASK_SECTION` | 要读取的二级标题名称，不含 `##`；未设置或空字符串时使用“今日主要任务”。 |

当前应用入口没有“空字符串表示全部章节”的配置方式。任务需使用 Markdown 的 `- [ ]` / `- [x]` 格式；支持任务缩进及 wikilink 显示名称转换。

## 使用方式

| 操作 | 结果 |
| --- | --- |
| 悬停顶部入口 | 探出后展开 |
| 移出已展开面板 | 保持展开 |
| 点击面板外 | 收起；编辑或固定时不收起 |
| 点击图钉 | 切换固定展开 |
| 点击勾选图标 | 修改原日记中的完成状态 |
| 双击任务文字或点击铅笔 | 进入文字编辑 |
| Return / Escape | 保存 / 取消本次编辑 |
| 菜单栏 → 退出 ScreenDeck | 退出常驻应用 |

菜单栏退出前请先保存或取消编辑；退出不是自动暂存功能。编辑任务文字会替换该任务的原始文本，包含链接的任务建议先在测试副本验证。

## 数据与隐私边界

- 当前任务数据从本地 vault 读取，写回本地 Markdown。
- 当前实现不调用 AI、不上传笔记、不采集屏幕、摄像头或浏览记录。
- 若 vault 由 iCloud、Obsidian Sync 等同步，文件同步由对应服务决定，不受 ScreenDeck 控制。
- 任务目前按文件行号定位。不要同时在其他编辑器中重排或修改同一日记；稳定任务 ID、外部修改冲突检测和接续快照尚未实现。
- 没有任务与读取失败分别显示；读取失败时可尝试重新读取。已有缓存任务不代表本次读取成功。

## 开发与测试

```bash
swift build
swift test
```

当前测试覆盖任务解析、Markdown 修改、编辑输入校验、面板收起策略及布局尺寸。本次版本运行 18 项测试通过；测试不替代实际屏幕上的动画、中文输入、鼠标热区和多显示器验收。

迁移仓库后如出现旧 ModuleCache / PCH 路径错误，可以在新的临时目录重新构建，不必删除个人数据：

```bash
screen_deck_build_dir="$(mktemp -d /tmp/screendeck-build.XXXXXX)"
swift test --scratch-path "$screen_deck_build_dir"
```

## 常见问题

**没有显示任务？**

检查 vault 路径、Daily Notes 配置、当天日记文件及二级标题是否一致。仅支持当前日记，不会自动汇总整个 vault。

**悬停没有展开？**

先通过菜单栏打开，确认应用仍在运行。入口位于屏幕顶部中央；多显示器、菜单栏自动隐藏和全屏行为仍需进一步验证。

**修改源码后界面没变？**

运行中的进程不会热更新。先退出旧实例，再重新执行 `swift run ScreenDeck`；避免同时启动多个版本。

**这是任务接续助手了吗？**

目前是任务面板基础版本，还不能自动保存工作上下文、判断任务进度或恢复其他应用状态。

## 后续方向

- 不依赖 Obsidian 的本地任务与稳定任务 ID。
- 用户确认的进度、下一步、材料链接和接续记录。
- 在授权边界内整理工作线索，保留不依赖 AI 的使用路径。
- 实体按钮复用软件暂存入口，真实保存成功后再反馈。
- 左、右、底部吸附，以及多显示器适配。

这些是计划，不代表当前版本已经支持，也不构成固定交付时间承诺。
